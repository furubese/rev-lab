rev-lab: バイナリ解析演習

ルール

  • 各バイナリにフラグを入力すると Correct! が出ます。フラグを見つけてください。
  • フラグの形式は CTF{...} です。
  • 使えるツール: file / strings / objdump / gdb / strace / less
  • 環境はブラウザ内で完結しています。リロードすると初期状態に戻ります。

問題

Level 1: はじめの一歩

このバイナリにフラグを入力すると Correct! が出ます。フラグを見つけてください。

./crackme1
Enter the flag: ???

Level 2: 見えないフラグ

このバイナリにフラグを入力すると Correct! が出ます。フラグを見つけてください。

./crackme2
Enter the flag: ???

ターミナル

答えと解説

自力で解いてから開いてください。

Level 1 の答えと解説を見る

1. まず正体を調べる

~ # file crackme1
crackme1: ELF 64-bit LSB executable, x86-64, ..., statically linked, ..., not stripped
  • statically linked: ライブラリが中に埋め込まれている。ltrace は使えない
  • not stripped: 関数名（シンボル）が残っている。main を名前で指定して逆アセンブルできる

2. 中の文字列を眺める

実行すると Enter the flag: と出るので、その文字列の周辺を見る。

~ # strings crackme1 | grep -C 3 "Enter the flag"
[A\A]A^A_]
<@u5H
@@CTF{strings_is_your_friend}
Enter the flag:
Correct!
Wrong!

表示メッセージと並んで CTF{...} 形式の文字列がそのまま見える。

3. 本当に比較相手か確かめる（objdump）

~ # objdump -d -M intel --disassemble=main crackme1 | less
  401973: lea    rax,[rip+0x7d696]   # 47f010   ← フラグ文字列のアドレス
  40197a: mov    QWORD PTR [rbp-0x98],rax
  ...
  4019ba: call   40a510 <_IO_fgets>   ← 入力を読む
  ...
  4019ec: mov    rdx,QWORD PTR [rbp-0x98]
  4019f3: lea    rax,[rbp-0x90]
  4019fa: mov    rsi,rdx              ← 第2引数: フラグ
  4019fd: mov    rdi,rax              ← 第1引数: 入力
  401a00: call   401120 <_init+0x120> ← strcmp
  401a05: test   eax,eax
  401a07: jne    401a1a               ← 0以外なら Wrong!

x86-64 では第1引数が rdi、第2引数が rsi。入力とフラグを比べ、戻り値が0（一致）なら Correct!。

補足: 静的リンクでは strcmp が CPU に合わせて実装を切り替える仕組み（IFUNC）経由で呼ばれるため、<strcmp> ではなく <_init+0x120> と表示される。

4. 動的に確かめる（gdb）

~ # gdb ./crackme1
(gdb) break *0x401a00
(gdb) run
Enter the flag: test
(gdb) x/s $rdi
0x7ffc...:  "test"
(gdb) x/s $rsi
0x47f010:   "CTF{strings_is_your_friend}"

答え

CTF{strings_is_your_friend}

学び: フラグを平文で埋め込むと strings だけで見えてしまう。

Level 2 の答えと解説を見る

1. strings では見えない

~ # strings crackme2 | grep CTF
（何も出ない）

メッセージ（Enter the flag: / Correct! / Wrong!）は見えるが、フラグらしき文字列がない。どこかで加工されている。

2. 動きを観察する（strace）

~ # strace ./crackme2
...
write(1, "Enter the flag: ", 16)
read(0, "test\n", 1024)
write(1, "Wrong!\n", 7)

ファイルを開くなどの怪しい動きはない。判定はプログラム内部だけで行われている → 逆アセンブルを読む。

3. main を読む（objdump）

~ # objdump -d -M intel --disassemble=main crackme2 | less

(a) 入力の前処理

  401973: mov    QWORD PTR [rbp-0x98],0x17   ← 定数 23 を保存
  ...
  4019b7: call   40a580 <_IO_fgets>           ← 最大 0x80 バイト読む
  ...
  4019df: call   401140 <_init+0x140>         ← strcspn(入力, "\n")
  4019e4: mov    BYTE PTR [rbp+rax*1-0x90],0x0 ← 改行の位置を 0 にして切る

(b) 長さチェック

  4019f6: call   401160 <_init+0x160>         ← strlen(入力)
  4019fb: cmp    QWORD PTR [rbp-0x98],rax     ← 23 と比較
  401a02: je     401a1d                       ← 23文字なら先へ、違えば Wrong!

→ フラグは 23 文字。

(c) 1文字ずつ比較するループ

  401a1d: mov    QWORD PTR [rbp-0xa0],0x0     ← i = 0
  401a2a: ...
  401a3b: movzx  eax,BYTE PTR [rax]           ← 入力[i]
  401a3e: xor    eax,0x3a                     ← 入力[i] ^ 0x3a
  401a41: mov    ecx,eax
  401a43: lea    rdx,[rip+0xa8686]  # 4aa0d0 <enc>
  401a54: movzx  eax,BYTE PTR [rax]           ← enc[i]
  401a57: cmp    cl,al                        ← 一致しなければ Wrong!
  401a71: add    QWORD PTR [rbp-0xa0],0x1     ← i++
  401a80: cmp    rax,QWORD PTR [rbp-0x98]
  401a87: jb     401a2a                       ← i < 23 の間くり返す

条件は 入力[i] ^ 0x3a == enc[i]。

4. enc の中身を取り出す

~ # objdump -s -j .data crackme2
 4aa0d0 796e7c41 42554865 485f4c5f 48495358  yn|ABUHeH_L_HISX
 4aa0e0 565f6555 511b47..                    V_eUQ.G

gdb でも見られる: (gdb) x/23xb &enc

5. 逆算する

XOR は同じ値でもう一度 XOR すると元に戻る（(a ^ k) ^ k == a）。つまり 入力[i] = enc[i] ^ 0x3a。

0x79 ^ 0x3a = 0x43 → 'C'
0x6e ^ 0x3a = 0x54 → 'T'
0x7c ^ 0x3a = 0x46 → 'F'
0x41 ^ 0x3a = 0x7b → '{'
...

23 バイト分くり返すと全体が得られる（手元に Python があれば bytes(b ^ 0x3a for b in bytes.fromhex("796e7c41...")).decode()）。

答え

CTF{xor_reversible_ok!}

学び: XOR で隠しても strings からは消えるだけで、鍵（0x3a）と暗号化データ（enc）は同じバイナリに入っている。処理を読めば逆算できる。
